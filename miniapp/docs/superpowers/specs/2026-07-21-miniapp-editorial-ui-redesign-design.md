# 九型芯之力小程序 Editorial UI 改版设计

## 1. 目标与范围

本阶段只改造小程序与 H5 共用的视觉和交互层，不修改九型测试算法、登录、预约、支付、接口协议与后台管理逻辑。

需要覆盖现有七个页面：

- 首页 `pages/index/index`
- 答题 `pages/test/test`
- 结果 `pages/result/result`
- 关系合盘 `pages/relation/relation`
- 学习 `pages/learn/learn`
- 预约 `pages/booking/booking`
- 我的 `pages/profile/profile`

目标是把当前偏统一玻璃卡片的界面升级为具有品牌辨识度的编辑设计系统，同时保持微信小程序的清晰、轻快和可操作性。

## 2. 设计原则

### 2.1 任务优先

遵循微信小程序设计指南，每个页面只设置一个主要行动：

- 首页：开始测试
- 答题页：选择当前答案
- 结果页：阅读结果；付费报告为明确但不抢占基础结果的转化入口
- 学习页：继续学习或按类型查看推荐
- 预约页：提交预约
- 我的：登录或管理档案

### 2.2 丰富但有秩序

视觉丰富度来自以下组合，而不是重复增加阴影、渐变和圆角：

- 人物或心理主题插画
- 非对称图文编排
- 大小尺度变化
- 九种人格徽章体系
- 编辑式课程封面
- 纸张纹理和少量拼贴元素
- 页面之间不同的内容节奏

### 2.3 微信原生可用性

- 以 375px / 390px 设计宽度为基准
- 主要触控区域不小于 44px
- 底部导航保持四项
- 保留系统返回行为和安全区
- 表单使用清楚的字段标签、就近错误和提交反馈
- 加载优先采用局部骨架或局部反馈

## 3. 品牌视觉系统

### 3.1 色彩

| Token | 色值 | 用途 |
|---|---:|---|
| `--nx-bg` | `#F3EFE7` | 温暖纸张背景 |
| `--nx-surface` | `#FFFDF8` | 内容表面 |
| `--nx-ink` | `#17212B` | 主文字、深色品牌区 |
| `--nx-muted` | `#68727C` | 次级文字 |
| `--nx-blue` | `#315BEA` | 主操作、选中态 |
| `--nx-coral` | `#C9472D` | 商业转化按钮，满足白字对比度要求 |
| `--nx-coral-soft` | `#F5DDD6` | 珊瑚色浅背景和装饰 |
| `--nx-jade` | `#347B62` | 成长、课程、成功状态 |
| `--nx-lilac` | `#A99BD4` | 辅助插画和柔和层次 |
| `--nx-line` | `#DEDCD5` | 分割线与弱边框 |
| `--nx-error` | `#B42318` | 表单和请求错误 |
| `--nx-focus` | `#2449C7` | 聚焦描边 |
| `--nx-overlay` | `rgba(10, 17, 25, .56)` | 弹层遮罩 |

禁止在组件中继续随意添加无语义的蓝色、紫色和阴影值。九型徽章允许使用受控的蓝、珊瑚、琥珀、绿色阶，但同一页面不得形成彩虹噪音。

九型强调色固定为：1 `#315BEA`、2 `#C9472D`、3 `#B86A12`、4 `#8065B5`、5 `#347B62`、6 `#42658D`、7 `#C47B18`、8 `#A43D35`、9 `#5D7766`。

### 3.2 字体层级

使用微信和系统中文字体，避免 H5 外部字体加载造成小程序差异。

- Display：48–56rpx，700–800，用于首页和结果核心标题
- Heading：34–40rpx，700–800，用于区块标题
- Title：28–32rpx，600–700，用于卡片标题
- Body：26–29rpx，400–500，行高 1.55–1.75
- Label：21–24rpx，600–700，用于元数据和标签

标题允许紧凑排版，正文保持充分行高。长文优先换行，不用过度省略。

### 3.3 九型人格徽章

1～9 号使用统一徽章组件：

- 数字始终是主体
- 支持小、中、大三种尺寸
- 支持默认、选中、结果展示三种状态
- 每种型号可有稳定强调色，但形状、边框和排版保持一致
- 不能用 emoji 代替正式图标或徽章

组件接口至少支持 `typeId`、`size`、`selected`、`label` 与 `disabled`。未知或无效型号统一回退为中性墨灰样式。

### 3.4 插画与图片

- 首页：抽象人物侧脸、纸张拼贴、能量色块
- 答题：本阶段使用脑、心、腹三中心对应的三张低干扰抽象插画，不为 12 道题分别制作插画
- 结果：人物肖像或抽象人格头像，强化情绪与辨识度
- 学习：真实老师头像、编辑式课程封面
- 预约和我的：以信息和任务为主，减少装饰插画

图片必须预留固定比例，避免异步加载导致页面跳动。非首屏图片使用懒加载。

### 3.5 视觉资产清单

视觉资产由项目自行生成或绘制，不引入来源与授权不明确的第三方素材：

- 首页主视觉：1 张，1200×900 WebP，目标 `< 220KB`，兜底为 CSS 色块与九型徽章
- 三中心抽象插画：3 张，720×480 WebP，单张 `< 120KB`，加载失败时不展示
- 九型结果视觉：9 张，640×640 WebP，单张 `< 150KB`，兜底为现有头像与型号徽章
- 课程兜底封面：3 张，800×500 WebP，单张 `< 140KB`，兜底为现有 wheel 图与色块

纸张颗粒优先使用轻量 CSS 背景。首屏关键图使用普通加载或预加载；仅非首屏图片使用 `lazy-load`。现有“所有图片必须懒加载”的视觉测试同步调整。

## 4. 组件系统

### 4.1 按钮

- Primary：钴蓝背景，白字，用于页面唯一主操作
- Conversion：珊瑚色，用于付费或预约等商业转化
- Secondary：透明或浅表面，深色文字和边框
- Text：无容器，用于重试、查看更多和次要操作
- Disabled：降低对比度并禁止交互
- Loading：按钮原位显示加载状态，避免布局跳动

### 4.2 内容容器

不再所有内容都套相同白色大圆角卡片，改为四类容器：

- Editorial Hero：图像、标题和主行动的非对称组合
- Compact Panel：数据、摘要和短操作
- Media Row：课程、老师和历史记录列表
- Quote / Insight：语录与解释性内容，可使用纸张底色和特殊排版

圆角控制在 16–32rpx 的有限层级。阴影仅用于浮层和重点媒介卡，普通内容依赖边框、背景和留白分层。

### 4.3 表单

- 字段标签始终可见
- 输入高度至少 88rpx
- 错误显示在字段下方
- 预约草稿能力保留
- 选择器需要清晰的当前值和箭头提示
- 提交中禁止重复点击

### 4.4 导航

- 保留四项 tabBar：测一测、学一学、约课程、我的
- 图标统一使用相同笔画和尺寸
- 继续使用 `pages.json` 原生 tabBar，不引入 custom-tab-bar
- 选中态背景直接绘制进 `selectedIconPath` PNG，并同时使用钴蓝文字颜色
- 页面内容预留底部安全区

## 5. 页面设计

### 5.1 首页

- 首屏由品牌插画、核心价值和“开始测试”组成
- 九型徽章作为可识别品牌元素，但不做大型神秘圆盘
- 关系合盘、学习内容采用不同尺度的非对称入口
- 推荐课程使用带封面的媒体行；本阶段点击后只切换到现有“学一学”tab，不新增课程详情路由
- 删除与开始测试竞争的重复大按钮

### 5.2 答题页

- 固定展示进度和题号
- 题目使用大字号，选项占据主要视线
- 情境插画只占辅助区域
- 选择后即时反馈，保留现有自动前进逻辑
- 上一题操作降级为文本或弱按钮

### 5.3 结果页

- 首屏明确展示主型号、名称和人格视觉
- 基础解读、三中心、成长/压力内容分层展开
- 深度报告使用独立深色编辑模块，保持价格和状态清晰
- 存档、分享、海报、合盘、预约按主次重新排序
- 海报视觉同步新品牌系统，但不改变现有生成流程的业务语义

### 5.4 关系合盘

- 两个人格选择区使用徽章组件
- 结果采用“双人关系画像 + 优势/摩擦/建议”三段结构
- 同时选择前只显示一个主要生成按钮

### 5.5 学习页

- 老师区使用真实媒体布局，不再使用普通信息卡
- 课程封面需要有独立视觉，课程列表展示标签和时长
- 语录使用编辑式引用排版
- 九型图鉴使用紧凑徽章网格，避免九张同形大卡
- 课程卡本阶段只承担展示，不直接打开 `url`；主要行动沿用现有“先完成测试/查看学习内容”tab 切换

### 5.6 预约页

- 顶部使用简短说明和预约类型切换
- 表单按联系信息、学习意向、补充信息分组
- 固定一个明确提交按钮
- 保留校验、草稿和错误恢复行为

### 5.7 我的

- 未登录状态强调登录后可获得的价值
- 登录后按用户信息、测试历史、预约历史分区
- 历史记录改用媒体行/时间线，不使用重复大卡
- 退出登录保持低优先级并与正常操作分离

## 6. 技术实现边界

- 优先在 `src/styles/apple-mobile.css` 中建立语义 token 和基础组件
- 页面保留 scoped 样式，但只处理页面特有布局
- 可复用徽章、图标或视觉单元应抽取到组件或通用样式，避免七个页面复制
- 不引入重型 UI 框架
- 不依赖小程序不支持的复杂 CSS 滤镜
- H5 与微信小程序都必须可运行
- 插画资产使用压缩 WebP/PNG，并声明尺寸
- 允许更新 `scripts/ui-compat.test.mjs` 中绑定旧视觉实现的断言；必须保留并强化触控尺寸、禁用态、错误反馈、安全区、条件编译和图片尺寸等行为/可访问性断言
- 旧 CSS token 可在一个过渡周期内保留为新语义 token 的别名，新页面不得继续新增旧 token

## 7. 状态与异常

所有异步内容至少覆盖：

- 初始加载
- 成功
- 空状态
- 网络错误与重试
- 提交中和重复点击保护
- 登录受限环境提示

H5 保持公开页面可预览，受限功能采用固定行为：

- 保存档案：按钮禁用，显示“请在微信小程序内登录后保存”
- 深度报告购买：按钮禁用，显示“请在微信小程序内完成存档与支付”
- 微信分享/保存海报：隐藏微信专属动作，仅保留重新测试和关系合盘等公开流程
- 预约提交：表单允许预览和填写，提交按钮禁用并提示“请在微信小程序内提交预约”；草稿能力继续保留
- 我的：继续使用现有“请在微信小程序内登录”状态

小程序结果页尚未存档时不展示未经接口确认的默认价格，改为“先存档，查看报告价格”。存档成功后查询报告状态和真实价格；查询中展示局部加载，失败时提供重试，已解锁时展示查看报告入口。该调整只改变展示状态与错误恢复，不改变支付接口或订单业务逻辑。

## 8. 验证标准

- 运行现有 `npm run test:config`
- 运行 `npm run build:h5`
- 运行 `npm run build:mp-weixin`
- 在 375px、390px 和平板宽度检查无横向滚动
- 检查 tabBar、安全区和固定操作不遮挡内容
- 检查文字对比度与 44px 触控区域
- 检查加载、空、错误、禁用和选中状态
- 检查 H5 中保存、支付、分享和预约不会错误触发微信登录或支付流程
- 检查报告价格仅在状态接口成功返回后展示
- 对首页、答题、结果、学习、预约、我的进行截图或渲染验收

## 9. 实施阶段

1. 建立设计 token、通用容器、按钮、表单和徽章
2. 改造首页、答题页和结果页，形成主视觉基线
3. 改造学习、关系合盘、预约和我的
4. 更新图片资产与 tabBar 图标
5. 完成 H5、小程序构建和视觉验收

后台管理功能属于下一阶段，不与本次 UI 改版混合实施。

## 10. 用户验收后的视觉层次深化

首轮真实 H5 验收反馈为“结构清晰但仍然单调”。第二轮在不改变页面信息架构和业务逻辑的前提下，增加以下视觉层次：

- 首页主视觉由“文字区 + 独立矩形图片”升级为全幅编辑海报，图片、标题、色块与徽章形成前后层关系。
- 九型徽章可作为非交互悬浮构图元素，但不得排成圆盘、星盘或妨碍正文阅读。
- 关系、学习、推荐内容使用不同尺寸和不同媒介比例的 Bento 编排，避免同宽、同高、同背景重复。
- 页面背景允许使用轻量 CSS 纸张颗粒、章节色带和局部大色块，但不能依赖高成本全局毛玻璃。
- 答题页根据 `head/heart/gut` 使用受控氛围色和插画背景；题目与选项仍然是视觉中心。
- 答案选项加入编号、左侧强调、选中填充和明确按压反馈，不能只依赖边框颜色。
- 使用 180–260ms 的 opacity/transform 动效表达页面进入、选项按压和题目切换；`prefers-reduced-motion` 下关闭非必要动效。
- 手机维持单列任务流；约 768px 宽度时首页主视觉、Bento 内容和答题图文可使用双栏布局。
- 所有装饰层必须 `pointer-events: none`，纯装饰徽章容器还必须设置 `aria-hidden="true"`，不能遮挡按钮或产生重复的 1～9 读屏内容；有信息意义的九型列表继续正常暴露给辅助技术。
- 纸张纹理只能使用静态 CSS 渐变/背景，不得使用全页 `filter`、`backdrop-filter` 或持续动画纹理。

深化后的验收重点不是“装饰数量”，而是主视觉、信息模块和留白之间形成明显的大小、疏密和明暗节奏。必须在 375px、390px 和约 768px 三个视口进行实际 H5 视觉检查，确认无横向滚动、文字不压图、正文对比度达到 AA、按钮可点击/可聚焦且装饰层不截获事件。

## 11. 最终确认方向：老师品牌与课件出版物

用户否定了以性格测试工具、九型徽章和复杂 Bento 为主的表达。最终确认的产品定位是“老师个人品牌 + 系统课程 + 课件资料”，本节覆盖并取代第 10 节的视觉深化方向。

### 11.1 信息优先级

1. 认识老师和教学理念
2. 查看课程与学习路径
3. 浏览课件、音频和视频资料
4. 预约课程或咨询
5. 九型自测作为辅助入口

首页不能再以九型数字、测试科技感或抽象人格图为主视觉。

### 11.2 视觉语言

- 风格参考高质量出版社、独立书店、讲座系列和成熟知识付费产品。
- 主色改为纸张米白 `#F6F1E7`、炭墨 `#20252B`、深绿 `#335B4A`、朱红 `#B94A3D`、沙色 `#DCCDB5`。
- 老师真实照片、课程封面和课件缩略图是主要视觉资产。
- 大标题允许具有中文书刊/访谈式排版气质，正文继续使用系统中文字体保证加载和可读性。
- 通过图片裁切、细分割线、章节编号、书脊/纸张比例和留白制造丰富度，不依赖大量圆角卡片、渐变或阴影。

### 11.3 首页

- 首屏使用老师主图、姓名/身份、可信度说明和“开始学习”唯一主按钮。
- 老师图片来源优先读取后台 `home.teacherTeaser.image`，失败时使用本地老师兜底图。
- 展示一门精选课程和一组课件资料，使用书刊封面比例。
- “九型自测”作为小型次要入口，不与老师和课程争抢视觉重心。
- 首页内容优先使用现有 site-config 缓存并后台刷新；加载失败使用本地老师/课程兜底，不产生白屏。

### 11.4 学一学

- 顶部形成完整老师介绍：照片、姓名、身份、简介和标签。
- 课程内容采用出版物封面、目录、资料类型（课件/视频/音频）和时长信息。
- 语录采用编辑式引用排版。
- 九型图鉴降为页面后部的辅助资料索引，不使用九张醒目的大卡。
- 本阶段不新增课程详情页，课程卡仍为展示；主要操作引导测试或预约。

### 11.5 数据兼容

- `normalizeTeachers` 必须兼容现有后台 `home.teacherTeaser`，避免后台老师资料与小程序脱节。
- 后台真实 `teacherTeaser.title` 为“姓名｜身份”组合字段：优先按中文/英文竖线拆成 `name` 和 `title`；无法拆分时保留完整标题为 `name`，身份回退为 `eyebrow` 或“九型人格导师”，不能把同一组合字符串重复显示两次。
- `normalizeCoursewareItems` 继续兼容 `home.courses.items`。后台提供的 `badge/title/description/bullets` 是内容主体；本地按标题或稳定索引补充不同的封面、资料类型和时长，并保留 `bullets`，不能假定后台存在这些字段。
- 本地课程补充表至少覆盖当前三类课程：个人成长、领导力/团队、家庭关系；分别使用不同课程封面与“课件/视频/音频”组合标签。
- `siteConfig` 的学习内容/区块识别必须包含 `home.teacherTeaser`，确保仅配置老师资料时缓存不会被后续不完整响应覆盖。
- 新增内容图片解析规则：绝对 HTTPS 原样使用；`/static/...` 保持小程序本地资源；`/assets/...` 与 `/api/public/site-uploads/...` 基于 `API_BASE` 的 HTTPS origin 转为绝对 URL；非法或不安全地址回退本地图片。
- 图片加载失败只回退一次到项目本地素材，避免错误循环。
- 状态语义固定为：首次无缓存时先显示本地兜底和加载提示；请求成功但明确返回空老师/空课程区块时显示“资料整理中”空状态；请求成功但旧配置缺少区块时继续使用本地兜底；请求失败时保留缓存/兜底并显示非阻断错误与重试。
- 老师照片作为有意义图片提供可访问名称；课程封面与相邻标题重复时设为装饰图片，避免读屏重复。
- 不修改后台接口、测试算法、登录和支付逻辑。

### 11.6 验收

- 首页第一眼必须明确这是老师课程与学习资料产品，而不是测评工具。
- 老师照片和课程封面占据主要视觉面积，文字层级像正式出版物而非 SaaS 卡片。
- 375px、390px 保持单列阅读；768px 可形成老师图文双栏与课程书架布局。
- 所有主要控件满足 44px 触控、键盘焦点和 AA 对比度。
