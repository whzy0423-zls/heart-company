# 九型芯之力小程序全页面视觉升级设计

## 1. 目标与范围

在已完成的现代能量首页基础上，一次性升级其余六个页面：

- `pages/test/test`：答题
- `pages/result/result`：测试结果
- `pages/relation/relation`：关系合盘
- `pages/learn/learn`：学习中心
- `pages/booking/booking`：预约
- `pages/profile/profile`：我的

目标是建立“统一品牌系统 + 页面独立气质”的完整体验。页面应明显属于同一个产品，但不能把首页的四彩渐变机械复制到所有场景。

本阶段不修改测试算法、登录、支付、预约接口、后端协议、分享和海报业务语义，也不新增页面路由。允许为 H5 限制和报告价格确认增加小型展示状态与条件编译守卫，但不得改变接口参数、支付流程或服务端状态含义。

## 2. 全局设计原则

### 2.1 统一但不重复

所有页面共用：

- 浅蓝灰背景与低透明度环境光晕
- 深色高对比主文字
- 受控圆角与阴影层级
- 统一按钮、标签、状态卡和表单语言
- 44px 以上触控区域
- H5 与微信小程序双端无障碍语义

每页使用独立主题：

| 页面 | 主题 | 主要色彩 |
|---|---|---|
| 答题 | 专注与探索 | 蓝紫 |
| 结果 | 人格身份与成长 | 人格动态色 + 深蓝 |
| 合盘 | 连接与关系 | 紫粉 |
| 学习 | 知识与成长 | 青绿 |
| 预约 | 行动与联系 | 橙蓝 |
| 我的 | 档案与长期成长 | 深蓝紫 |

### 2.2 一个主行动

- 答题：选择当前答案
- 结果：阅读结果；未存档时突出存档，报告 `ready` 时突出解锁，预约始终是次级入口
- 合盘：生成合盘解读
- 学习：固定突出“先完成测试，建立你的学习地图”
- 预约：提交预约
- 我的：未登录时突出登录；登录后只在资料编辑区突出“保存资料”，不新增管理档案操作

### 2.3 状态优先

视觉改造不得掩盖原有状态：加载、空内容、网络错误、重试、提交中、禁用、登录限制、支付状态和无效参数都必须清楚呈现。

## 3. 公共视觉系统

### 3.1 语义色彩

在 `src/styles/apple-mobile.css` 中补充语义 token，并保留现有 token 兼容：

- `--nx-page-bg: #F3F6FC`
- `--nx-surface: #FFFFFF`
- `--nx-surface-soft: #F8FAFF`
- `--nx-ink: #0F172A`
- `--nx-muted: #64748B`
- `--nx-line: rgba(51, 65, 85, .10)`
- `--nx-blue: #2563EB`
- `--nx-purple: #7C3AED`
- `--nx-pink: #C0267E`
- `--nx-teal: #0F766E`
- `--nx-green: #15803D`
- `--nx-orange: #C2410C`
- `--nx-danger: #B42318`

页面特色渐变仅在首屏、关键结果和主要媒介区域使用。普通信息区使用浅色表面、边框和留白，防止视觉过载。

### 3.2 共用样式单元

公共样式只包含多个页面都需要的基础单元：

- `.nx-page-hero`：页面主题首屏容器
- `.nx-section-head`：区块标题与辅助说明
- `.nx-panel`：浅色信息面板
- `.nx-state`：加载、空和错误状态
- `.nx-tag`：标签和元数据
- `.nx-focusable`：统一键盘聚焦和按压基线

页面特有的图形、卡片网格和内容布局继续放在各页面 scoped CSS 中，避免全局样式膨胀。

### 3.3 可访问性与交互

- 可点击 `view` 同时提供 H5 `role="button"` 与微信 `aria-role="button"`。
- H5 可点击视图提供 `tabindex="0"`、Enter/Space 操作和可见焦点。
- 按钮和卡片按压反馈只使用 `opacity` 与 `transform`。
- 动画时长 150–260ms，`prefers-reduced-motion` 下关闭装饰动画和交互过渡。
- 次级文字不得浅于 `#64748B`；普通文字对比度目标至少 4.5:1。

## 4. 答题页设计

### 4.1 性别选择阶段

- 顶部使用蓝紫主题标题和简短说明。
- 两个选择使用并列的大型能量卡，保留现有 button 语义和性别权重逻辑。
- 男生使用深蓝青，女生使用紫粉；颜色之外继续保留文字和图形区分。
- 移除外围重复玻璃层，页面更直接。

### 4.2 答题阶段

- 顶部展示题号、总题数和清晰进度条。
- 题目大字号居中或左对齐，成为页面视觉中心。
- 选项改为独立浅色选择面板，选中时使用蓝紫边框、浅色背景和状态图形。
- “上一题”降级为文本按钮；选择答案仍沿用现有锁定和自动前进逻辑。
- 快速重复点击保护、计时器清理和卸载逻辑不变。

## 5. 结果页设计

### 5.1 人格身份首屏

- 使用结果型号对应头像、数字、名称、英文关键词和摘要。
- 首屏背景根据主型号使用受控强调色，但正文保持高对比。动态色直接沿用现有 `TYPES_INFO[type].color` 分类映射为页面 class，不新建另一套九型配色数据。
- 人格描述和 `persona` 采用清晰层级，不全部塞入同一种卡片。

### 5.2 数据与成长内容

- 基本恐惧、核心欲望使用双栏驱动力面板。
- 三中心使用高对比进度条和明确百分比。
- 副型/侧翼、压力方向、成长方向使用不同结构而非重复白卡。
- 成长建议使用浅绿色洞察模块。

### 5.3 报告与操作

- 深度报告使用独立深色模块，展示查询中、未存档、可购买、失败重试和已解锁状态。
- 价格仅在接口成功返回后展示，保留现有支付逻辑。
- 分享、海报、合盘、预约、重新测试按主次分组，不形成一排同等级按钮。
- H5 微信专属动作继续隐藏或禁用，不触发微信登录和支付。
- Canvas 海报流程和小程序条件编译保持不变。

报告展示状态允许进行以下有限脚本调整：

| 状态 | 进入条件 | 展示 | 唯一主操作 |
|---|---|---|---|
| `needs-save` | 初始、尚无 `recordId` | “先存档，查看报告价格” | 存入档案 |
| `status-loading` | 存档成功后查询状态 | 局部加载，不显示价格 | 无重复操作 |
| `ready` | 状态接口成功、未解锁且返回有效正数价格 | 展示接口价格和报告简介 | 小程序内解锁 |
| `status-error` | 状态查询失败或未返回有效价格 | “报告价格获取失败” | 重试查询 |
| `unlocked` | 接口确认已解锁或支付成功 | 报告内容加载/失败/正文 | 查看或重试报告 |

`reportPriceCents` 初始改为 `null`。状态判断优先级为：先判断 `unlocked`；已解锁时直接进入 `unlocked`，不要求价格。只有未解锁时才校验 `priceCents`，返回有限、正数价格进入 `ready`，否则进入 `status-error`。支付成功后仍沿用现有 `loadReportContent`。该调整只修正展示与恢复路径，不新增接口。

## 6. 关系合盘页设计

### 6.1 选择阶段

- 顶部使用紫粉连接主题首屏。
- “我的型号”和“TA 的型号”使用统一九型数字徽章网格。
- 选中态同时使用颜色、描边和勾选/连接图形，不只依赖颜色。
- 页面只保留一个“生成合盘解读”主按钮。

### 6.2 结果阶段

- 首屏展示双头像、连接线和契合指数。
- 相处底色、潜在摩擦和相处建议分别使用蓝紫、橙粉、青绿语义模块。
- 双方核心驱动使用双列摘要。
- 无效参数、跳转中状态继续明确展示，并保留返回测试页逻辑。

## 7. 学习页设计

### 7.1 老师区

- 使用青绿主题标题区。
- 老师资料使用头像、姓名、身份、标签和简介的媒体布局。
- 加载、失败与重新加载操作在原位置展示，不用整页遮挡。

### 7.2 课程与课件

- 课程使用横向封面媒体卡，展示 badge、时长、标题和说明。
- 图片固定比例、继续懒加载；加载失败时保留色块和文字结构。
- 点击行为继续沿用当前展示边界，不新增课程详情路由。

### 7.3 语录与图鉴

- 老韩语录使用编辑式引用卡，强化文字节奏。
- 九型图鉴使用紧凑数字徽章网格，避免九张同样的大卡。
- 页面底部始终保留一个测试引导按钮，文案为“先完成测试，建立你的学习地图”，继续调用现有 `goTest` 并切换到首页。不判断是否已测试，不新增“继续学习”状态或课程详情行为。

## 8. 预约页设计

### 8.1 页面结构

- 顶部使用橙蓝主题，说明老师联系与匹配学习方式的价值。
- 表单分为预约类型、联系信息、学习意向与补充信息三个视觉区域。
- 每个字段标签始终可见，输入高度至少 88rpx。
- 选择器提供明确当前值和箭头图形，不使用 emoji。

### 8.2 表单状态

- 姓名和手机号错误继续显示在字段下方，并保留 `aria-invalid`。
- 草稿恢复、自动保存和提交成功后清理逻辑不变。
- 提交中按钮禁用并保留加载状态。
- H5 允许预览、填写和保存本地草稿，但提交按钮禁用，显示“请在微信小程序内提交预约”，且不绑定 `submit` handler。微信小程序继续使用原提交按钮、校验和接口调用。

## 9. 我的页面设计

### 9.1 未登录状态

- 使用深蓝紫成长档案首屏，清楚说明登录后可获得的价值。
- H5 保留禁用提示，小程序保留微信一键登录。

### 9.2 登录后状态

- 用户头像、昵称、主型和成长摘要组成顶部身份区。成长摘要只使用现有数据：主型 `user.mainType`、测试记录数量 `records.length`、预约数量 `bookings.length`；加载中显示占位，不新增后端字段。
- 微信资料编辑改为紧凑编辑面板，保留 chooseAvatar、nickname 和保存逻辑。
- 测试历史与预约历史改为时间线/媒体列表，突出日期、类型和状态。
- 加载、同步失败、重试与空记录状态保持独立，不把失败显示成空列表。
- 登录后不新增“管理档案”功能。资料编辑区的“保存资料”是该区域唯一主按钮；历史区不设置新的主操作。退出登录与危险操作保持低优先级并与正常操作分离。

## 10. 数据、错误与平台边界

- 不新增网络请求和后端字段。
- 学习页继续先显示本地缓存，再静默刷新；请求失败保留缓存内容。
- 结果页继续校验缓存结果结构，失效时提供明确提示。
- 合盘继续校验传入和选择的型号。
- 预约和资料提交继续使用现有错误归一化文案。
- 允许新增下表列出的 H5/微信平台守卫，除此之外不扩大条件编译范围。
- 所有新增图片容器必须预留尺寸，非首屏图片继续懒加载。

### 10.1 平台操作矩阵

| 页面/操作 | H5 | 微信小程序 |
|---|---|---|
| 答题、合盘、学习公开内容 | 正常使用 | 正常使用 |
| 结果页存档 | 禁用按钮：“请在微信小程序内登录后保存”；不调用 `saveRecord` | 正常调用 `saveRecord` |
| 报告状态查询 | 未存档时不查询 | 存档后查询 |
| 报告购买 | 禁用按钮：“请在微信小程序内完成存档与支付”；不调用 `unlockReport` | `ready` 状态正常调用 `unlockReport` |
| 分享好友 | 隐藏微信分享按钮 | 保留 `open-type="share"` |
| 生成/保存海报 | 保留现有禁用提示，不调用微信 API | 保留生成、保存和长按行为 |
| 预约提交 | 禁用提示，不调用 `submit`；草稿继续保存 | 正常校验和提交 |
| 我的登录 | 保留现有禁用提示 | 正常微信登录 |
| 头像昵称编辑 | 仅登录态出现；H5 不新增模拟登录 | 微信登录后正常使用 |

### 10.2 页面 × 状态矩阵

| 页面 | 必须覆盖的状态 |
|---|---|
| 答题 | 性别选择、答题、已选、锁定、上一题 |
| 结果 | 结果有效、结果失效跳转、存档中/成功/失败、报告五态、海报生成中/成功/失败 |
| 合盘 | 选择、结果、无效参数、跳转中 |
| 学习 | 缓存内容、首次加载、静默刷新、错误重试、空语录 |
| 预约 | 草稿恢复、字段错误、提交中、成功、请求失败、H5 禁用 |
| 我的 | 未登录、登录中、资料加载、列表加载、列表错误、空记录、资料保存中、登录失效 |

“加载、空、错误、重试”等验收仅要求在适用页面和异步区域覆盖，不为纯本地状态强行新增网络状态。

### 10.3 图片失败策略

- 老师头像、人格头像和用户头像：容器尺寸固定；失败后显示型号数字、姓名首字或品牌“九”字色块。
- 课程封面：固定比例；失败后显示主题渐变和课程序号/标签。
- 图片失败只影响视觉媒介，不隐藏标题、说明和主要操作。

## 12. 实施顺序

1. 公共 token、状态、表单和聚焦基线
2. 答题、结果、关系合盘核心体验链路
3. 学习、预约、我的内容与账户链路
4. 全局兼容测试、双端构建和多宽度视觉验收

虽然用户希望一次性完成，开发仍按上述内部阶段执行并在同一交付中完成全部六页。

## 13. 验收标准

- 六个页面与首页属于同一品牌系统，但拥有清晰不同的页面主题。
- 360、375、390、800px 无横向滚动和内容遮挡。
- tabBar、安全区、键盘焦点和底部操作不遮挡内容。
- 所有主要触控区域不小于 44px。
- 文字与背景具备足够对比度，功能含义不只依赖颜色。
- 适用页面的加载、空、错误、重试、禁用、选中、提交中和平台限制状态完整。
- 答题进度提供可理解的题号/总数文本；异步状态使用可见文字，必要时提供 `aria-live`；表单标签和字段错误与输入项就近对应。
- 海报弹层提供明确关闭操作，打开时不把关闭能力隐藏在遮罩点击中；本阶段不新增复杂焦点陷阱。
- 运行首页及六页相关兼容测试。
- H5 和微信小程序生产构建通过。
- 在 H5 对答题、结果、合盘、学习、预约和我的进行截图或渲染验收。
- 结果页截图通过开发态写入合法 `lastResult` 缓存准备；合盘分别使用直接选择和合法 query；学习使用缓存/默认内容并单独检查错误结构；预约检查 H5 禁用态；我的在 H5 检查未登录态，小程序登录态通过静态结构与构建产物检查。
- 完整测试中现有 `.env.production.example` 配置断言作为已知基线问题单独记录，不修改用户 `.env.development`。
