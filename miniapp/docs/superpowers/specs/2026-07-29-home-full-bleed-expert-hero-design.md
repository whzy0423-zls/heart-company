# 首页全幅导师视觉卡设计

## 目标

将首页当前“左侧文字介绍＋右侧窄画框”调整为更适合个人培训品牌推广的全幅导师视觉卡：导师人像成为主视觉，减少信息噪音，同时保留进入课堂和查看完整导师介绍的转化入口。

## 方案对比

### 方案 A：全幅人像＋底部轻量信息（采用）

- `portraitImage` 铺满导师主视觉卡，使用 `aspectFill`。
- 底部使用深蓝渐变遮罩，承载导师身份、课堂入口和“查看完整导师介绍”。
- 不显示长篇 `lead` 介绍，避免图片与文字争夺注意力。
- 点击主视觉卡继续预览 `detailImage`。

优点：视觉聚焦、专业感更强、保留推广动作；风险是图片裁切，需要稳定的人像构图和渐变遮罩。

### 方案 B：图片铺满并叠加完整文字

- 图片作为背景，保留标题、简介和 CTA 全部叠加。

优点：信息完整；风险是移动端容易拥挤，海报感较重，降低人像辨识度。

### 方案 C：纯图片无任何文字

- 只保留全幅图片和点击预览。

优点：最简洁；风险是用户不知道导师是谁，也找不到老师课堂入口，不适合企业客户转化。

## 交互与视觉

- 主视觉使用单一原生 `button`，避免嵌套交互控件。
- 高度约 `600rpx`，圆角、金色描边与深蓝阴影沿用现有品牌体系。
- 底部遮罩至少保留 92rpx 触达高度，标签使用暖米白，重点操作使用香槟金。
- 人像加载失败时显示“九”品牌占位；完整海报为空时不触发空预览。
- 不改变首页其它区块顺序、后台内容数据结构或课程入口路由。

## 数据与兼容

- 继续使用 `expertHero.portraitImage` 作为主视觉来源。
- 继续使用 `expertHero.detailImage` 作为完整介绍预览来源。
- 保留 `expertHero.image` 兼容别名，不改后台旧字段。

## 验证

- 增加首页契约测试：不再渲染长篇导师介绍；主视觉绑定 portraitImage；课堂入口与 detailImage 预览仍存在。
- 运行 `npm run test:config`、`npm run build:mp-weixin`。
- 检查生成 WXSS 无 `var(--*)`，并确认现有开发 watcher 可继续增量编译。
