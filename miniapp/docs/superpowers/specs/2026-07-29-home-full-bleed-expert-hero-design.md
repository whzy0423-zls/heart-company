# 首页全幅导师视觉卡设计

## 目标

将首页导师区调整为首屏内可完整看清的竖版导师人像卡：不裁切老师头部或身体，不使用大段姓名/简介遮罩，同时保留进入课堂和查看完整导师介绍的转化入口。

## 方案对比

### 方案 A：竖版完整人像＋底部轻量入口（采用）

- 导师卡约 `600 × 1040rpx`，居中展示并控制在常见手机首屏内。
- `portraitImage` 使用 `aspectFit`，完整显示老师头部和整张竖版人像，不做裁切。
- 移除姓名、职称和长篇 `lead` 的大面积文字遮罩。
- 底部只保留“查看完整导师介绍”和“进入老师课堂”两个轻量入口。
- 点击主视觉卡继续预览 `detailImage`。

优点：整张老师图片可见、人物识别清晰、首屏信息更干净；风险是卡片左右会保留少量呼吸空间，但比裁掉头部更符合当前诉求。

### 方案 B：图片铺满并叠加完整文字

- 图片作为背景，保留标题、简介和 CTA 全部叠加。

优点：信息完整；风险是移动端容易拥挤，海报感较重，降低人像辨识度。

### 方案 C：纯图片无任何文字

- 只保留全幅图片和点击预览。

优点：最简洁；风险是用户不知道导师是谁，也找不到老师课堂入口，不适合企业客户转化。

## 交互与视觉

- 主视觉预览与课堂入口继续使用平级原生 `button`，避免嵌套交互控件。
- 卡片宽约 `600rpx`、高约 `1040rpx`，使用圆角、金色描边、深蓝底和阴影。
- 图片使用 `aspectFit`；底部操作层尽量薄，避免挡住人物主体，并保留至少 88rpx 触达高度。
- 人像加载失败时显示“九”品牌占位；完整海报为空时不触发空预览。
- 不改变首页其它区块顺序、后台内容数据结构或课程入口路由。

## 数据与兼容

- 继续使用 `expertHero.portraitImage` 作为主视觉来源。
- 继续使用 `expertHero.detailImage` 作为完整介绍预览来源。
- 保留 `expertHero.image` 兼容别名，不改后台旧字段。

## 验证

- 增加首页契约测试：不再渲染姓名/长篇介绍遮罩；主视觉使用 aspectFit 完整绑定 portraitImage；课堂入口与 detailImage 预览仍存在。
- 运行 `npm run test:config`、`npm run build:mp-weixin`。
- 检查生成 WXSS 无 `var(--*)`，并确认现有开发 watcher 可继续增量编译。
