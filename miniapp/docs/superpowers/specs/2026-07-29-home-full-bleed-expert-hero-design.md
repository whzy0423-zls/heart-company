# 首页全幅导师视觉卡设计

## 目标

将首页导师区直接展示完整导师介绍海报：画面包含左侧介绍文字、老师人物和底部标语，不再使用单独人像 `portraitImage` 代替海报。海报在首屏内等比完整显示，并保留进入课堂入口。

## 方案对比

### 方案 A：完整导师介绍海报＋下方课堂入口（采用）

- 首页主视觉绑定 `detailImage`，直接显示完整 `teacher-poster.jpg` 海报。
- 首页移除顶部品牌名称/标语/头像画框，该品牌信息只在“我的”页面展示。
- 海报卡约 `640 × 1140rpx`，与 1024×1824 海报比例一致，尽量利用首页可用宽度并缩窄左右留白。
- 图片使用 `aspectFit`，完整显示左侧导师介绍、右侧人物和底部标语。
- 海报上不再叠加姓名、详情提示或课堂按钮，避免遮挡海报原始内容。
- 点击整张海报继续调用图片预览；“进入老师课堂”作为海报下方独立原生按钮。

优点：后台/官网设计的导师海报信息完整保留，用户一次看到导师资历、人物和品牌表达；风险是海报文字会缩小，因此卡片需尽量利用首屏可用高度。

### 方案 B：图片铺满并叠加完整文字

- 图片作为背景，保留标题、简介和 CTA 全部叠加。

优点：信息完整；风险是移动端容易拥挤，海报感较重，降低人像辨识度。

### 方案 C：纯图片无任何文字

- 只保留全幅图片和点击预览。

优点：最简洁；风险是用户不知道导师是谁，也找不到老师课堂入口，不适合企业客户转化。

## 交互与视觉

- 完整海报预览与课堂入口使用上下相邻的原生 `button`，避免嵌套交互控件。
- 海报卡宽约 `640rpx`、高约 `1140rpx`，使用圆角、金色描边、深蓝底和阴影。
- 图片使用 `aspectFit`；海报内部不放任何自定义遮罩，课堂按钮位于海报下方且至少 88rpx 高。
- 人像加载失败时显示“九”品牌占位；完整海报为空时不触发空预览。
- 首页删除 `home-nav` 品牌条；其它区块顺序、后台内容数据结构和课程入口路由不变。

## 数据与兼容

- 首页主视觉和完整图片预览都使用 `expertHero.detailImage`。
- `expertHero.portraitImage` 继续保留在视图模型中，供其它紧凑人像场景使用。
- 保留 `expertHero.image` 兼容别名，不改后台旧字段。

## 验证

- 增加首页契约测试：主视觉使用 aspectFit 完整绑定 detailImage；海报内部没有自定义文字遮罩；课堂入口与 detailImage 预览仍存在。
- 运行 `npm run test:config`、`npm run build:mp-weixin`。
- 检查生成 WXSS 无 `var(--*)`，并确认现有开发 watcher 可继续增量编译。
