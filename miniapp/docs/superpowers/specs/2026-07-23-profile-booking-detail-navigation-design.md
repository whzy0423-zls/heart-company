# 个人资料与预约详情导航设计

日期：2026-07-23

## 目标

将“我的”页从资料编辑与数据明细混合页面调整为清晰的个人总览：首页顶部头像/昵称进入独立个人资料页；“我的预约”进入预约列表，点击记录进入独立详情页。保持现有接口、登录体系、蓝紫渐变视觉与平台边界不变。

## 页面结构

### 我的页 `pages/profile/profile`

- 登录态顶部身份卡整体可点击，头像、昵称和右侧箭头共同表达“进入个人资料”。
- 移除当前页面内的“微信资料、一键同步、头像昵称输入、保存资料”整块内容。
- 保留主型、测试数、预约数统计与测试历史预览。
- “我的预约”卡片改为明确的可点击入口，展示预约总数和接口返回的第一条预约摘要。后端按 `create_time DESC` 返回，因此第一条就是最近预约，客户端不再重复排序。
- 预约入口在加载、错误、空状态下都可进入预约记录页。卡片外壳本身不承担按钮语义，内部“查看预约记录”主体是独立可点击控件；错误态的“重试”是与入口主体并列的原生按钮，阻止冒泡且绝不触发导航，不影响测试历史展示。

### 个人资料页 `pages/profile-edit/profile-edit`

- 页面标题为“个人资料”。
- 进入页面时校验本地 token 并读取 `/wx/userinfo`；未登录或 401/403 时清除 token，只执行一次 Toast，并使用 `uni.switchTab({ url: '/pages/profile/profile' })` 回到“我的”。离开页面或发生鉴权失效后，旧异步响应不得继续写状态。
- 展示当前头像与昵称，保留微信规范能力：`chooseAvatar`、`type="nickname"`、一键同步与保存资料。
- 一键同步继续使用 `uni.getUserProfile`；获取不到数据时提示用户使用头像昵称控件手动补充。
- 保存继续调用现有 `PUT /wx/userinfo`，成功后返回的数据刷新当前表单并留在资料页，用户自行返回；“我的”页通过 `onShow` 重新加载最新资料。未保存修改在用户离开资料页时丢弃，不做草稿持久化。
- 请求、同步、保存均有独立 loading，防止重复提交；异步响应需防止离开页面后覆盖状态。

### 预约记录页 `pages/booking-records/booking-records`

- 页面标题为“预约记录”。
- 使用现有 `GET /miniapp/bookings` 获取当前用户最多 50 条预约。
- 列表卡片展示：预约类型、中文状态、学习意向或默认摘要、创建时间、脱敏手机号。
- 支持加载态、错误重试和空状态；空状态提供“去预约”按钮，切换到预约 Tab。
- 点击某条记录，将完整记录连同当前 token 作为会话归属暂存到一个只负责跨页传递的预约会话工具，并导航到预约详情页；URL 同时携带预约 ID，便于校验。

### 预约详情页 `pages/booking-detail/booking-detail`

- 页面标题为“预约详情”。
- 路由 ID 先 `decodeURIComponent`、去空白并规范化为仅包含数字的字符串；缺失、非法编码、空白或非数字 ID 不发请求，直接进入“预约记录不存在”空状态。数字/字符串 ID 统一使用字符串比较。
- 从预约会话工具读取所选记录并校验 URL ID、当前 token 与会话归属；任一不匹配立即清除缓存。缓存缺失时重新调用预约列表接口，只在后端当前返回的最近 50 条中查找对应 ID。产品不承诺超过最近 50 条的直接深链恢复。
- 详情字段：预约编号、类型、中文状态、称呼、完整手机号、学习意向、期望时间、留言、创建时间。
- 空字段统一显示“未填写”，状态至少支持 `pending`、`confirmed`、`completed`、`cancelled`，未知状态显示原值或“处理中”。
- 加载失败提供重试；记录不存在显示可返回预约列表的空状态。详情页离开、退出登录、token 变化或 ID 不匹配时清除预约会话缓存。

## 数据与工具边界

- 不新增后端接口，不改变预约数据库结构。
- 新增 `src/utils/bookingDisplay.js`，负责预约 ID、类型、状态、空值和手机号脱敏的纯函数格式化。未知类型优先显示原始非空值，未知状态显示原始非空值；空值显示“未填写”。手机号少于 7 位或已含脱敏符号时保持原值，正常号码仅保留前三位与后四位。
- 新增 `src/utils/bookingSession.js`，只在模块内存中保存当前选择的完整预约记录和所属 token；读取时必须同时匹配规范化 ID 与当前 token，退出详情、退出登录、用户切换或校验失败时清除。详情页仍可通过最近 50 条列表恢复，避免把内存缓存作为唯一数据源。
- 个人资料页直接复用 `normalizeWechatProfile`、`hasProfilePayload`、`getWechatProfilePayload` 和现有用户 API。

## 视觉与可访问性

- 延续现有 `nx-page-hero`、`nx-panel`、`ios-card`、蓝紫渐变和大圆角体系。
- 可点击身份卡与预约卡内部的“查看预约记录”主体在 H5 提供 `role="button"`，微信提供 `aria-role="button"`，并包含 `tabindex="0"`、Enter/Space 激活、可见焦点、按压反馈、可读 `aria-label` 和至少 88rpx 触控高度。预约错误态的重试按钮与导航主体是并列焦点项，不嵌套交互语义。
- 详情页使用成组信息卡，不把字段压成表格；状态用低饱和色标签表达。
- 手机号只在详情页完整展示，列表页脱敏。
- 加载、错误和空状态始终展示可读文字；适用的异步状态容器使用 `aria-live="polite"`。

## 平台边界

- 微信小程序支持一键同步、头像选择、昵称编辑和保存。
- H5 若存在有效登录 token，可编辑昵称并调用 `PUT /wx/userinfo` 保存；一键同步与头像选择显示禁用微信引导，不渲染 `getUserProfile`/`chooseAvatar` handler。H5 通常无法从页面建立微信登录，因此无 token 时仍统一回到“我的”。
- 预约列表与详情在 H5/微信均可通过既有 token 和接口展示；无 token 或鉴权失效统一清 token、抑制旧响应，只 Toast/导航一次并 `switchTab` 回“我的”。

## 测试与验收

- 纯函数测试覆盖状态中文、类型中文、空字段与手机号脱敏。
- 会话工具测试覆盖设置、读取、数字/字符串 ID 等价、token 归属、旧会话清理、ID 不匹配清理和显式清除。
- UI 契约测试覆盖新增路由、我的页移除内嵌编辑区、身份入口、预约入口、微信/H5 条件编译和详情字段。
- 页面契约覆盖非法 ID 不请求、最近 50 条恢复边界、鉴权失效只导航一次、详情离开清理、H5 微信 handler 缺失、Enter/Space 激活语义，以及错误态重试不导航和两个控件可分别聚焦。
- Fresh 运行相关单测、UI 兼容测试、H5 构建和微信小程序构建。
- 微信产物检查个人资料页保留 `chooseAvatar` 与 nickname input，H5 产物不绑定微信同步能力。
