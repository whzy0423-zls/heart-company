# 小程序个人专家品牌全站视觉升级设计

**日期：** 2026-07-28  
**状态：** 已确认  
**恢复基线：** `miniapp-ui-baseline-before-training-refresh-20260728` → `b5b3780`

## 1. 项目定位

小程序的核心定位不是普通课程商城，也不是单纯的九型测试工具，而是：

> 由个人专家主理、面向公司与企业客户的九型人格培训与团队成长品牌，通过个人形象、专业内容、真实案例、体验工具和预约流程建立信任并促进合作。

现有测评、关系合盘、视频音频课件、预约和个人档案继续保留，但重新安排主次：

- 老师本人是品牌中心。
- 企业服务是主要转化目标。
- 课堂内容是专业能力证明。
- 九型测试小游戏是获客与传播体验。
- 个人档案承接用户长期使用。

## 2. 目标与非目标

### 2.1 目标

1. 让首次访问者在首屏理解老师是谁、服务什么企业问题、下一步如何合作。
2. 全站形成统一、克制、可信的视觉语言，避免页面之间像不同产品。
3. 保留现有功能和接口行为，优先升级信息层级、视觉和交互。
4. 让后台已发布的视频和音频课件在小程序中自然展示。
5. 把九型测试小游戏从品牌主角调整为高价值互动入口。
6. 保证加载、缓存、错误、空状态、触控尺寸和安全区体验一致。

### 2.2 非目标

- 本轮不重写测评计分算法。
- 本轮不引入复杂动画、3D 或高成本图片特效。
- 本轮不删除关系合盘、深度报告、预约记录等现有功能。
- 本轮不把小程序改造成大型培训机构的多讲师商城。

## 3. 已确认的视觉方向

采用“个人专家工作室”风格：

- 浅色内容区。
- 石墨蓝主视觉。
- 暖灰页面背景。
- 香槟金少量点睛。
- 真实老师照片和专业证据优先于抽象装饰。
- 无大面积绿色、紫色、粉色或多彩渐变竞争。

### 3.1 核心颜色

| 语义 | 建议值 | 用途 |
|---|---:|---|
| 品牌深色 | `#202A37` | 首屏、关键案例、深色品牌区 |
| 品牌蓝灰 | `#314052` | 次级品牌面、媒体封面 |
| 点睛金 | `#DFBC7F` | 主按钮、重点数字、标签 |
| 页面背景 | `#F5F3ED` | 暖灰品牌背景 |
| 卡片背景 | `#FFFFFF` | 内容卡片与表单 |
| 主文字 | `#1D2733` | 标题和正文 |
| 次文字 | `#64748B` | 辅助说明 |
| 边框 | `#E0DDD4` | 卡片与分隔 |
| 成功 | `#157A55` | 仅状态语义 |
| 错误 | `#B42318` | 仅错误语义 |

### 3.2 视觉规则

- 页面横向留白统一为 `28–32rpx`。
- 主要卡片圆角统一为 `28–32rpx`，内部卡片为 `20–24rpx`。
- 主要按钮高度不低于 `88rpx`，小按钮触控区域同样达到 `88rpx`。
- 正文建议 `28–30rpx`，辅助短标签最低 `22–24rpx`。
- 阴影克制，以层级分隔为主，不使用高饱和发光。
- 同一层级使用一致的线性图形语言，减少手绘装饰和互相冲突的主题色。

## 5. 首页设计

首页按以下顺序组织：

1. 品牌导航：老师/品牌名称、身份短句、个人档案入口。
2. 个人专家 Hero：老师真实照片、专业头衔、价值主张。
3. 双操作：主操作“预约企业培训沟通”，次操作“认识老师/查看课堂”。
4. 信任数据：专业年限、服务企业/团队、课程评价等可验证内容。
5. 企业培训服务：管理者领导力、团队沟通、跨部门协作等场景。
6. 精选案例或客户反馈。
7. 九型测试小游戏独立互动区。
8. 老师课堂精选：优先展示已发布的视频和音频独立课件。
9. 关系合盘、个人档案等次级能力。
10. 页面末尾再次提供企业预约入口。

轮播图继续支持后台配置，但不再强制位于页面第一位。轮播内容建议用于课程现场、企业案例和客户评价。

### 5.1 首页数据来源与兜底

首页不写入不可验证的“服务企业数量”“满意度”等演示数字。只展示后台已有配置或明确的稳定默认文案。

| 首页模块 | 首选数据 | 次选数据 | 缺失处理 |
|---|---|---|---|
| 品牌名称 | `home.miniappHome.brand` | `site.brandName` | 使用“九型芯之力” |
| 老师姓名/头衔/简介 | `home.teacherTeaser.title/lead` | 学习页第一位老师资料 | 隐藏简介长文，仅保留品牌价值主张 |
| 老师照片 | `home.teacherTeaser.image` | `home.teacherTeaser.fallbackImage` | 图片加载失败显示“九”字品牌头像 |

### 6.3 结果承接

## 8. 组件与样式架构

先整理 `src/styles/apple-mobile.css`，建立真正被页面使用的语义 Token，并逐页减少硬编码颜色。

建议创建或抽取：

- `NxPageShell`：页面宽度、横向留白、安全区。
- `NxExpertHero`：老师身份和个人品牌首屏。
- `NxSectionHeader`：标题、说明和“查看全部”。
- `NxCard`：统一卡片表面、边框、圆角和按压态。
- `NxButton`：主按钮、次按钮、文字按钮、禁用态。
- `NxAsyncState`：加载、旧缓存、空、错误、重试。
- `NxMediaCard`：视频、音频、系列课程和进度。
- `NxProofStats`：资历和可信数据。

为控制本轮风险，组件只在重复明显且能保持现有逻辑不变时抽取，不做无关的大规模重构。

### 8.1 `NxAsyncState` 落地契约

创建 `src/components/NxAsyncState.vue`，统一以下 props：

- `state`: `loading | stale | empty | error`
- `title`: 主提示
- `description`: 补充说明
- `actionText`: 可选操作文字
- `busy`: 重试进行中

组件声明 `emit('action')`。存在 `actionText` 时显示操作按钮；点击按钮触发 `action` 事件，由页面执行重试或跳转。`busy=true` 时按钮禁用并显示处理中状态，避免重复触发。

统一触发与行为：

| 状态 | 触发条件 | 展示行为 |
|---|---|---|
| Loading | 首次请求且无缓存 | 加载标记/骨架，不显示空内容 |
| Stale | 有缓存但刷新失败 | 保留已有内容，在内容上方显示轻提示与重试 |
| Empty | 请求成功且有效项目为 0 | 说明当前没有内容，并提供课堂/首页等下一步 |
| Error | 首次请求失败且无缓存 | 错误提示、重试按钮、必要的辅助去向 |

课堂、学习页和首页先接入统一组件；记录页和档案页复用同一视觉类或组件。组件文案面向访客，不出现后台操作提示。

## 10. 异常与状态设计

全站统一四类异步状态：

1. **Loading：** 首次进入使用骨架或清晰加载状态。
2. **Stale：** 新数据刷新失败时继续展示旧内容，并提供重试。
3. **Empty：** 解释当前没有内容，并提供可执行的下一步。
4. **Error：** 简短错误提示、重试按钮和辅助去向。

客户端空状态不展示后台操作说明。管理诊断信息保留在测试或管理端。

### 11.2 视觉与运行验收

- 小屏手机、普通手机、横屏和较大屏幕检查。
- 所有主要触控区域不低于 44pt/88rpx。
- 文字对比度满足可读性要求。
- 每轮修改后执行 `npm run dev:mp-weixin`。
- 确认输出 `DONE Build complete. Watching for changes...`。
