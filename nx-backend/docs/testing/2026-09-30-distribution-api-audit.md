# 代理中心接口验收报告（2026-09-30）

本轮通过真实 HTTP 请求、生产路由与鉴权中间件、PostgreSQL 17 验证代理创建、邀请注册、会员付款、佣金、管理端查询与结算。测试使用独立本地数据库、虚拟测试账号和本地 XZN 签名网关，没有真实扣款、转账、短信或线上用户数据变更。本报告证明当前工作区代码的行为，不代表已部署的生产版本已经更新。

## 实测订单示例

通过管理员 API 创建一级代理，用户通过邀请码注册后由上级 API 升为二级、三级代理，再让买家通过三级代理的邀请码注册。代理号与邀请码是同一个 `agentCode`，数据库数字 ID 不是邀请码。

注册邀请码支持有效的各级代理；购买时手填优惠码只接受有效一级代理。购买优惠码不等于重新分配邀请归属，已注册账号登录时不补绑代理。

本地测试将三级佣金各设置为 10%，VIP 月卡原价 29.00 元、邀请优惠 5.00 元。此比例仅是测试配置，未改变生产费率。

| 检查项目 | 接口/账本实际结果 |
| --- | --- |
| 买家实付 | 24.00 元 |
| 一级、二级、三级佣金 | 每级 2.40 元，合计 7.20 元 |
| 管理端订单总额 | 24.00 元，未按三级重复累计 |
| 管理端佣金记录 | 3 条，关联同一订单和买家，保留规则版本 |
| 每个代理自身概览 | 各自 2.40 元 |
| 支付通知重复到达 | 仍 3 条佣金；会员到期时间不重复延长 |
| 规则改为每级 20% 后重放旧通知 | 旧订单仍每级 2.40 元，历史快照保持不变 |
| 新人工确认订单实付 24.00 元 | 使用新规则每级 4.80 元；重复确认不重复生成 |

独立财务用例还验证实付 100.00 元、三级各 10% 时合计 30.00 元；原价 100.00 元、优惠后实付 79.01 元时，每级按分向下取整为 7.90 元、合计 23.70 元。

## 覆盖范围

| 链路 | 结果与覆盖 |
| --- | --- |
| 代理创建 | 管理员创建一级；直接邀请用户升下级；三级拒绝继续创建；重复创建冲突 |
| 邀请码查询 | 有效、大小写、前后空格、缺失、不存在、暂停、误传数字 ID |
| 链接进入 | 公共邀请 API 记录点击；官网支持 `agentCode` 与旧 `agent` 参数 |
| 注册归属 | 短信凭据本地注入；真实注册 API 绑定一次；注册事件和归属一致 |
| 防补绑/抢绑 | 既有账号登录不补绑、不改已有归属；直接 bind 被拒绝；重复注册不抢归属 |
| 层级和权限 | 非直属用户、跨树创建被拒绝；App token 不能访问后台；代理 token 不能访问管理员 API |
| 数据范围 | 伪造 agentId/appUserId/path 不扩大查询范围；他人订单状态不可读取 |
| 在线付款 | H5 使用 XZN；创建本地网关订单，校验签名、实付金额、通道与付款状态 |
| 失败与待付 | 无效签名、金额不符被拒绝；待支付不生成佣金 |
| 人工收款 | App 保持客服模式；后台确认后同事务生成会员和佣金；故障时整笔回滚 |
| 幂等 | 重复付款通知、重复人工确认、重复退款均无重复权益或记账 |
| 无邀请 | 正常付费开会员，不产生代理佣金 |
| 管理端数据 | 用户归属、订单、佣金、分析汇总、代理自身概览、结算记录可读取并对账 |
| 规则版本 | 激活互斥、历史订单快照保持、新订单用新规则 |
| 结算 | 预览、预占、审核、付款凭证、重复付款拒绝；并发预占和冲正竞争回归 |
| 退款 | 未结算佣金冲正、会员回退；晚到成功通知不重新开通；已付款结算凭证保留 |

完整 HTTP 旅程中的“admin reconciliation”表示订单与报表金额对账，不表示调用外部真实支付平台的主动查单。真实网关支付、真实银行打款、生产部署和浏览器逐页点击验收均不在本轮完成范围。

## 修复内容及影响

1. **客服人工收款漏佣金**：`admin_app_ops.go` 原先直接提交会员与订单，现提交前调用在线付款共用的佣金快照函数，按实付金额计算。佣金写入失败时订单和权益一起回滚。已支付订单的幂等返回保留。
2. **密码登录绕过注册归属规则**：`app_password_auth.go` 保留旧客户端 `agentCode` 参数兼容，但登录不再新增或修改邀请归属；注册绑定保持原流程。
3. **代理后台下级编号不一致**：`distribution.go` 下级创建复用现有六位随机码生成器，继续保留直属邀请、层级与数据库唯一约束。现有代理号不重写。
4. **管理端统计范围误导**：管理员接口原本不支持日期筛选，界面调整为明确“全局累计、近 30 天趋势”；代理保留日期筛选，标题匹配查询范围；修正金额图例、去除虚假的 `A用户ID` 代理号预览。

未修改 App/H5 的付款入口、原生工程、支付 SDK、会员价格或到期算法。共享后端登录和人工确认行为会同时适用于调用这些接口的客户端，属于上述缺陷修复；App 仍使用客服流程，H5 仍使用 XZN。

另修正分销 PostgreSQL 测试夹具的 schema 截取边界，避免无关聊天迁移使分销测试初始化失败。这只修改测试，不修改产品数据库迁移。

## 尚未解决的明确限制

- **已打款后退款没有自动追偿**：真实 PG 回归证明，先支付 100 元、结算佣金 10 元，再退款，佣金会变为 `reversed`，原 `paid` 结算单的金额、时间和凭证仍保留。再次获得 10 元佣金时，下一批预览仍可完整结算 10 元，不自动扣回之前已支付的 10 元。“已结算佣金”概览会下降，不代表钱已追回。当前需关联付款结算单与冲正记录人工核账，后续若自动化需明确追偿和抵扣规则。
- **历史漏记未回填**：人工确认修复作用于后续确认订单。没有按当前规则批量重算历史账，以免把今天的费率套到过去订单。
- **H5 海报操作尚未适配**：现有保存/图片分享仍调用原生 `Gal`、临时目录与 `File`。本轮只审计接口，没有修改 Web 图片下载/分享实现。文字邀请码及注册链接链路已核对。
- **短信登录体验差异**：短信登录先消费验证码再验证邀请码，错误或暂停邀请码会让本次验证码失效；密码注册先验证邀请码。本轮记录此差异，未修改验证码流程。
- **列表有上限**：管理员订单/佣金列表最多返回 500 条，部分代理列表返回 200 条；当前 `total` 是返回条数。大量历史数据的完整分页/导出能力不能由本次小规模旅程推出。
- 本轮未运行生产环境金融写入或负载压测，也未对所有非代理功能作全产品验收。
