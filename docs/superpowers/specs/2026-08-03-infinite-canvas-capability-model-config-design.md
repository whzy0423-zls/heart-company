# 无限画布按能力独立模型配置设计

## 目标

无限画布为每个浏览器用户提供四套互不影响的模型配置：图片、视频、文本和音频。每套配置独立保存 API Base、API Key、模型 ID 和协议类型，并由对应能力的画布节点使用。

配置保存在用户当前浏览器的本地存储中，不写入后台数据库，也不与其他用户共享。

## 当前问题

现有 `use-config-store` 以“渠道”为核心：一个渠道保存一份 API Base、API Key 和协议，渠道下多个模型共享凭据。虽然模型带有图片、视频、文本、音频能力标签，但凭据边界仍然是渠道，而不是能力类型。

现有画布节点已经能够按能力筛选模型，并在发起请求时解析模型对应的渠道配置，但这不符合以下目标：

- 图片配置变更不影响视频、文本或音频。
- 每种能力可以使用完全不同的 API 地址、密钥、协议和模型 ID。
- 用户可以在一个清晰的配置入口完成四类设置。

## 配置层级

模型凭据放在无限画布的应用级配置层，不放在项目或节点中。

- 应用级：维护图片、视频、文本、音频四套独立配置。
- 项目级：不复制 API Key，避免项目数据携带凭据。
- 节点级：保存生成参数，并在需要时保存模型 ID 覆盖值；默认使用对应能力的应用级模型 ID。

## 数据模型

新增统一的能力配置结构：

```ts
type CapabilityModelConfig = {
  apiBase: string;
  apiKey: string;
  apiFormat: "openai" | "gemini" | "ark";
  modelId: string;
};

type CapabilityConfigs = {
  image: CapabilityModelConfig;
  video: CapabilityModelConfig;
  text: CapabilityModelConfig;
  audio: CapabilityModelConfig;
};
```

图片、视频、文本和音频原有的专属生成参数继续保留在 `AiConfig` 中，例如图片尺寸、视频时长、文本推理强度、音色和音频格式。

## 本地持久化与迁移

配置继续使用 Zustand `persist` 写入浏览器 `localStorage`。

迁移规则：

1. 新格式存在时直接读取四类能力配置。
2. 旧格式只有渠道配置时，根据旧的 `imageModel`、`videoModel`、`textModel`、`audioModel` 找到对应渠道。
3. 将渠道的 API Base、API Key、协议和实际模型名分别复制到对应能力配置。
4. 某类旧模型无法解析时，仅为该类使用默认空配置，不影响其他三类。
5. 保留原本地存储键，使用版本字段或结构检测完成原位迁移，避免用户配置整体丢失。

## 配置界面

在无限画布内提供一个明确的“模型配置”入口。配置面板分为四个标签或折叠区域：

- 图片模型
- 视频模型
- 文本模型
- 音频模型

每个区域至少包含：

- 接口协议
- API Base
- API Key（密码输入框）
- 模型 ID

各区域展示对应的专属参数。修改和保存某一区域时只更新该能力配置，不覆盖其他能力。

配置面板需提供密钥显示/隐藏、字段完整性提示和保存反馈。密钥只在当前浏览器内持久化。

## 节点与请求链路

请求配置解析统一为：

```text
节点类型或生成模式
  → 确定 image/video/text/audio 能力
  → 读取对应 CapabilityModelConfig
  → 应用节点模型 ID 覆盖（如存在）
  → 校验该能力的 API Base、API Key、模型 ID
  → 调用对应生成服务
```

节点不能读取其他能力的凭据。例如视频生成缺少 API Key 时，只提示配置视频模型，不回退到图片或文本密钥。

模型选择器只展示当前能力可用的模型。第一阶段每种能力维护一套凭据和一个默认模型 ID；节点仍允许保存模型 ID 覆盖，但共享该能力的凭据。

## 错误处理

- 缺少 API Base：提示“请先配置图片/视频/文本/音频模型 API Base”。
- 缺少 API Key：提示对应能力的 API Key，随后打开配置面板的对应区域。
- 缺少模型 ID：提示对应能力的模型 ID。
- 请求鉴权失败：只指向当前能力配置。
- 旧配置迁移失败：该能力回退为空配置，其余能力继续可用。

## 安全边界

- API Key 不进入画布项目、节点元数据、导出文件或 URL。
- 日志和错误消息不输出完整 API Key。
- 配置存储在浏览器 `localStorage`，清理站点数据会删除配置。
- 浏览器本地配置适合当前“每个用户自行配置”的产品模式，但不提供跨设备同步。

## 测试

1. Store 单元测试：四类配置独立更新，修改一类不改变其他三类。
2. 迁移测试：旧渠道配置可正确迁移到四类能力配置。
3. 解析测试：每种能力返回自己的 API Base、API Key、协议和模型 ID。
4. 节点测试：图片、视频、文本、音频节点只使用对应配置。
5. 错误测试：缺失字段时提示正确能力，不错误回退。
6. UI 测试：四个配置区域可以独立填写和保存。
7. 构建与类型检查：无限画布测试、TypeScript 和生产构建通过。

## 非目标

- 不把 API Key 保存到后台数据库。
- 不实现跨浏览器或跨设备同步。
- 不在每个节点重复填写 API Key。
- 第一阶段不支持同一种能力配置多套凭据；后续可在能力配置下扩展多个预设。
