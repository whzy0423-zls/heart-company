# 当前人物卡口吻切换设计

## 目标

聊天回答始终采用当前会话所选人物卡的九型口吻。切换人物卡后，新会话请求立即使用新卡型号；用户主卡型号仅作为资料背景，不再覆盖当前人物卡口吻。

## 方案

- 后端继续以会话 `cardId` 查询当前人物卡，并把 `ConversationCard` 传入 RAG/LLM 层。
- 在所有普通聊天提供商共用的系统提示词解析入口中，根据 `ConversationCard.MainType` 追加可信的“当前人物卡口吻”指令。
- 为一至九号分别定义简短、可辨识但不刻板模仿的表达风格；明确当前人物卡优先于用户档案里的主型号。
- OpenAI 与 Anthropic 的用户上下文补齐当前人物卡名称、关系、型号、翼型和画像，与 MiniMax 保持一致。
- 人物卡文本作为不可信参考数据处理：名称和关系各限八十字，画像限八百字，并转义参考区段分隔符。
- 技能会话保持隔离：存在 `RuntimeInstructions` 时不注入人物卡口吻。

## 数据流

`session.cardId` → 查询人物卡 → `rag.ConversationCard` → 统一系统提示词解析 → 当前型号口吻 → 各提供商同步/流式请求。

## 边界与错误处理

- 仅一至九号属于有效型号；缺失或非法型号时维持现有默认口吻。
- 二级人物卡仍只作为当前关注对象，不让模型冒充该人物。
- 用户当前消息可约束回答长度、格式和语言，但不会悄然改回主卡型号口吻。

## 测试

- 表驱动测试覆盖九种型号的口吻映射。
- 验证当前人物卡型号优先、无有效型号回退、技能会话隔离。
- 验证 OpenAI/Anthropic 用户上下文包含当前人物卡。
- 运行 `go test ./internal/llm ./internal/server`。
