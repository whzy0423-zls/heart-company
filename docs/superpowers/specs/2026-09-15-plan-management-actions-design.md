# 套餐管理操作设计

## 目标

让套餐列表直接提供可发现的编辑、上架和下架操作，并消除部署后权限码缓存导致的空操作列。

## 权限与数据流

- 页面挂载时重新请求 `/auth/codes`，更新前端 access store，再加载套餐列表。
- 只有 `App:PlanManagement:Write` 权限可执行编辑和上下架。
- 无写权限时不展示空操作列，改为只读提示，后端 PUT 权限校验保持不变。
- 上下架复用现有 `PUT /admin/app-plans/{code}`，提交完整套餐对象且只变更 `enabled`。

## 操作体验

- 操作列使用“编辑”以及“上架/下架”文字按钮，保证含义清晰。
- 上下架前展示套餐名称和影响说明；下架按钮使用危险态。
- 每行拥有独立加载状态，防止重复提交；成功后更新列表并提示结果。
- 编辑抽屉继续保留完整配置和上架状态开关，保存后刷新列表。

## 测试与验收

- 前端测试验证页面刷新权限、操作按钮、确认框和 PUT 调用。
- 类型检查和生产构建通过。
- 部署后用管理员会话确认四个套餐均显示编辑与上下架操作。
- 实际切换一个测试套餐状态后再恢复，验证列表与公开商品接口同步。
