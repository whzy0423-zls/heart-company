# H5 星之柠支付与后台订单管理设计

## 目标

将 `personality-test-mvp-2026-09-01.zip` 中的人格测试 H5 接入九型芯之力 Go 后端。H5 通过统一订单 API 创建星之柠支付，后台管理系统集中查询、查单和退款。PostgreSQL 是订单状态唯一数据源。

## 架构

- H5 不持有商户号、密钥、金额、回调地址或网关配置，只提交商品、目标和支付通道。
- Go 后端创建本地订单，调用星之柠统一下单并返回经过校验的 `pay_url`。
- 星之柠回调由 Go 后端验签、核对商户号/金额/平台订单号并幂等更新订单。
- 后台“第三方支付 / 星之柠 / 订单管理”读取同一订单表，支持详情、主动查单和全额退款。
- 压缩包中的 `data/orders.json` 仅作为历史样本导入来源，后续不再写入。

## 订单模型

订单保存本站订单号、用户标识、商品、金额（分）、币种、支付类型、网关 ID、平台订单号、本站状态、平台状态、支付 URL、目标 ID、创建/支付/退款时间和最近回调摘要。状态为 `pending`、`paid`、`cancelled`、`refunded`、`frozen`。

生产订单金额固定由商品目录决定。首个商品为 `30-day-action-plan`，价格 990 分。浏览器不能指定实际金额。

## API

- `POST /api/payments/orders`：H5 创建订单。
- `GET /api/payments/orders/{orderNo}`：H5 查询订单状态。
- `POST /api/xzn-pay/notify`：星之柠异步通知。
- `GET /api/admin/xzn-pay/orders`：后台分页查询。
- `GET /api/admin/xzn-pay/orders/{orderNo}`：后台详情。
- `POST /api/admin/xzn-pay/orders/{orderNo}/query`：向星之柠查单并同步。
- `POST /api/admin/xzn-pay/orders/{orderNo}/refund`：按本地金额全额退款。

## 安全与一致性

- 商户密钥继续加密存储且不返回浏览器。
- 下单只允许已配置的通道映射；首版支持网关 3、31、34、36、38。
- `pay_url` 必须为 HTTPS，且主机属于星之柠允许列表。
- 回调验签后核对 PID、订单号和精确金额；只有事务提交成功才返回 `success`。
- 重复回调和重复查单不得重复发放权益，已退款订单不得被延迟成功通知恢复。
- 后台查单和退款要求 `System:Payment:Config` 权限。

## 后台界面

星之柠页面拆为“支付配置”和“订单管理”两个子菜单。订单页提供状态、渠道、订单号和时间筛选，表格展示金额、用户、支付通道、平台订单号与状态，并提供详情、查单、退款操作。

## 测试

- Go 单元测试覆盖签名、订单状态转换、金额/PID 校验、重复回调、查单和退款。
- API 测试覆盖鉴权、分页筛选和浏览器不能控制价格。
- H5 测试覆盖创建订单、跳转安全 URL、回跳后轮询。
- 前端类型检查覆盖后台订单页面。

## 部署

先部署数据库表和兼容 API，再部署 H5，最后开启真实支付。回调地址为 `https://九型芯之力.com/api/xzn-pay/notify`。上线后以 0.01 元专用测试商品或平台沙箱联调；正式商品仍固定 9.90 元。
