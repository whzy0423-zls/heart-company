# 小程序课程配置与支付接入设计

## 目标

让管理员在「小程序管理」下统一维护可售的老师课堂课程、系列、单课和价格；让小程序只提交课程标识，由服务端读取已发布商品的价格并复用现有微信支付状态确认链路。

## 现状与边界

- `home.courses` 目前是官网/小程序的宣传课程卡片，只包含文案、封面和要点，不是可售商品，也没有订单权益模型。
- 老师课堂的 series/content 已有独立数据库、发布状态、访问权限、`priceCents` 和课堂订单接口。
- 小程序已有 `createWechatPaymentController`，课堂列表和详情已经通过 `/miniapp/classroom/orders` 接入下单、微信收银台和服务端状态确认。
- 价格的唯一可信来源是已发布 classroom series/content；客户端不提交金额，微信回调继续走现有验签和幂等落账。

## 方案

1. 将现有老师课堂管理目录挂到「小程序管理」下，并保留旧路径兼容，避免已有书签和权限失效。课件、视频系列、上传任务和价格按钮继续复用现有课堂页面与 API。
2. 在「小程序管理」下增加「课程产品」入口，复用现有 `home.courses` 编辑器，保留现有宣传课程数据并增加可售目标绑定字段。宣传卡片可绑定 `series` 或 `content` 的 ID；未绑定时继续走报名意向，不显示在线支付。
3. 课程产品编辑器通过课堂 API 读取可选的已发布系列/单课，展示绑定目标的标题、发布状态和价格；价格编辑在课堂商品管理中完成，课程产品页显示服务端返回的元金额，避免出现两套价格。
4. 小程序课程详情根据绑定目标进入课堂详情/购买流程；购买按钮使用现有支付控制器，流程为登录、服务端创建订单、微信支付、查询服务端状态、确认 `paid/owned` 后刷新内容。支付取消、超时和下架沿用既有错误处理。
5. 课程展示数据保留向后兼容：没有 `miniappCourseProducts` 或绑定字段时继续读取现有宣传课程；不把旧 `home.courses` 直接当作订单商品，也不把金额写死在小程序包内。

## 数据结构

在 `home.courses.items[]` 保留现有字段并支持以下可选字段：

```json
{
  "title": "九型人格与生命关系",
  "description": "看见自己，也读懂重要的人",
  "cover": "/assets/course.jpg",
  "purchaseTarget": { "type": "series", "refId": 21 },
  "enabled": true,
  "sortOrder": 10
}
```

`purchaseTarget` 只保存类型和 ID；标题、发布状态、权限和金额由 classroom public API 返回。未绑定或不可购买的目标不能创建订单。

## 后台交互

- 课程产品卡片增加「关联课堂商品」下拉框，可选已发布的 series/content。
- 绑定后显示「当前售价 ¥X / 人」和「支付入口由老师课堂商品控制」；管理员前往老师课堂的价格编辑即可调价。
- 老师课堂的价格输入改为人民币元展示，提交前转换成分，后端仍使用整数分并校验 paid 必须大于 0。
- 关闭支付总开关时，课程详情隐藏支付入口，但历史权益和订单查询不受影响。

## 错误处理与安全

- 后端下单仍只接收 `targetType` 和 `refId`，从数据库快照读取金额和标题。
- 课程绑定目标下线、免费、缺媒体或无权限时，小程序降级为查看/报名，不发起支付。
- 支付收银台成功不等于支付完成；只有服务端状态确认成功才显示已购买。
- 价格冲突、目标已购买、订单重复点击和回调延迟复用现有 classroom order 行为。

## 验证标准

- 后台菜单测试确认课程产品和老师课堂位于小程序管理下，并保留旧菜单兼容。
- 课程配置测试确认现有课程数据可读写、绑定字段可序列化、无绑定目标保持报名行为。
- 金额测试确认元/分转换、零价/负价、最大值和付费权限校验。
- 小程序测试确认绑定课程跳转课堂购买、未绑定课程跳转报名、支付成功必须等待服务端状态。
- 运行后台相关 Vitest、服务端 Go 测试、小程序 `npm run test:config` 和 `npm run build:mp-weixin`。
