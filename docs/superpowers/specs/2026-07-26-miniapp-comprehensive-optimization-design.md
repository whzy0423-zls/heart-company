# 小程序全面优化设计

## 目标

在保持现有视觉语言、业务路径和紫色首页结构不变的前提下，合并已完成的首页后台配置能力，并对小程序做一轮高影响、低风险的体验、性能、稳定性和代码质量优化。

## 原则

- 不重新设计页面，不改变核心文案层级和导航路径。
- 每项修改必须对应明确问题、自动化测试和可回滚提交。
- 优先减少首包负担、失败后的死路、重复操作和不可理解的状态。
- 不为追求文件变小而进行无关重构。

## 基线整合

将 `feature/miniapp-home-menu-config` 合并到新的优化分支。保留首页配置、后台折叠编辑器、固定入口映射、配置规范化和后端持久化测试；合并后先运行后台、Go、小程序完整测试与微信构建，确保优化建立在可发布基线上。

## 性能：非 Tab 页面分包

首页、学习、预约和个人中心继续留在主包。测试答题、结果、关系合盘、资料编辑、预约记录和预约详情放入小程序分包，页面文件与现有 URL 不移动，业务跳转路径保持不变。

项目配置测试必须验证主包只包含 Tab 页面、分包包含所有非 Tab 页面且无重复注册。微信构建后检查 `app.json` 的 `subPackages` 和实际分包目录。

## 结果页：可靠且可访问的海报流程

将海报绘制逻辑从超大页面中抽到独立工具，页面只管理状态与交互。海报弹层增加对话框语义、生成进度、失败状态和重试入口；图片尚未生成时不显示可执行的保存按钮，防止无反馈点击。

绘图工具接收 canvas、结果数据和运行时适配器，保持现有海报视觉。头像加载、canvas 查询和临时文件生成失败需要向页面返回可识别错误，不在工具内部弹 Toast。

## 学习中心：缓存与刷新状态

继续优先展示缓存内容。后台静默刷新失败时保留已有内容，并显示轻量、非阻塞的“当前展示缓存内容”提示和重试按钮；无缓存且首次加载失败时维持现有阻塞错误状态。刷新成功后提示自动消失。

状态提示使用 `aria-live`，重试期间按钮禁用，避免重复刷新。

## 预约页：草稿恢复控制

只有具有实际内容的草稿才恢复。恢复后显示轻量提示和“清空草稿”操作；清空时同步取消待执行的防抖写入、恢复默认预约类型和表单字段，避免旧定时器把已清空内容重新写回。

成功提交后仍清除草稿，不改变现有自动保存节奏和表单验证规则。

## 跨页面一致性

扩展现有 UI 契约测试，检查新增状态的可访问名称、加载中的禁用逻辑、对话框语义、稳定列表键和触控反馈。只修复审计中有证据的问题，不改动已具备完整加载、重试和重复提交保护的页面。

## 测试与验收

- 小程序：所有行为先写失败测试，再实现；完整运行 `npm run test:config`。
- 后台：首页管理 focused Vitest 与格式检查。
- 后端：站点配置相关 Go 测试。
- 构建：微信开发构建成功，检查主包/分包配置和首页动态入口 WXML。
- 代码：`git diff --check`、冲突标记检查、工作区状态检查。

## 非目标

- 不更换品牌配色、字体或卡片视觉。
- 不改支付、登录、测试算法和后台业务接口。
- 不引入新的 UI 组件库、状态管理库或埋点系统。
