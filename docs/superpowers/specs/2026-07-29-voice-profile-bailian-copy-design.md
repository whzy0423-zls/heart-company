# MiniMax 音色一键复制到阿里百炼设计

## 目标

在人声管理中为已有 MiniMax 人声档案增加“复制到百炼”操作。系统复用原档案保存的音频样本，在阿里百炼托管的 `MiniMax/speech-2.8-turbo` 上重新复刻，保留原 MiniMax 音色作为回退，并让新音色自动出现在芯之力模型配置的“阿里百炼 · 已复刻音色”列表中。

## 方案比较

1. **推荐：后端专用复制接口**
   - 前端只提交源档案 ID。
   - 后端读取并复用 `sample_asset_id`、样本名称和样本地址，创建 `provider=bailian` 的新档案并执行复刻。
   - 可集中处理重复提交、权限和失败重试。
2. **前端直接调用现有创建接口**
   - 改动较少，但复制规则、去重和来源校验散落在前端。
3. **原档案原地切换 provider**
   - 会丢失原 MiniMax 回退音色，不采用。

## 后端设计

- 新增 `POST /api/voice/profiles/{id}/copy-to-bailian`。
- 权限沿用 `Voice:Profile:Manage`。
- 仅接受源档案平台为 `minimax` 且存在有效音频样本的记录。
- 复制创建阶段按 `sample_asset_id` 加数据库事务锁，保证并发点击只生成一条百炼档案。
- 若已存在使用同一 `sample_asset_id` 的百炼档案：
  - `ready`、`cloning`：直接返回现有档案，避免重复创建或重复调用上游。
  - `draft`、`failed`：复用现有档案重新提交复刻。
- 若不存在：创建名称为“原名称（百炼）”的新档案，复制样本引用，provider 设为 `bailian`，再走现有百炼复刻逻辑。
- 原 MiniMax 档案不修改、不删除。

## 前端设计

- 人声列表中，MiniMax 档案显示“复制到百炼”按钮。
- 点击后展示确认提示，说明会保留原音色并复用原音频样本。
- 操作期间只锁定当前行；成功后刷新列表，并提示可到芯之力模型配置选择。
- 百炼档案、缺少样本的档案不显示该操作。

## 芯之力联动

- `/api/voice/options` 已返回所有 `ready` 克隆档案及其 provider。
- 芯之力 TTS provider 选择“阿里百炼”时，只展示 `provider=bailian` 的可用档案。
- 选择后保存最终百炼 `voiceId`，运行时直接用于百炼托管 MiniMax 合成。

## 错误处理

- 未配置百炼 API Key：返回明确配置提示。
- 样本缺失或没有公网对象地址：保留百炼档案并标记 `failed`，列表展示 `lastError`，支持重新提交。
- 重复点击：返回同一样本对应的现有百炼档案。

## 验收标准

1. MiniMax 人声档案可一键复制到百炼，无需重新上传音频。
2. 原 MiniMax 档案完整保留。
3. 重复操作不会创建多条相同样本的百炼档案。
4. 百炼复刻成功后，新档案状态为 `ready` 且拥有百炼 `voiceId`。
5. 芯之力选择阿里百炼协议后，可选择该音色并保存。
6. 现有 MiniMax 克隆、测试、删除及芯之力实时语音功能保持兼容。
