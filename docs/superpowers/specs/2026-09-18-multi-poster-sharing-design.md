# 多海报模板推广设计

## 目标

管理员可以发布多个代理推广海报模板；有代理权限的用户在手机端可以选择模板，自动填充自己的邀请码和官网 App 下载链接，并将生成结果保存到相册或交给系统分享。

## 方案

继续使用 `site_configs` 的 `distribution_poster` 配置，新增 `templates` 数组，同时保留当前单模板字段作为兼容输入。每个模板包含稳定 ID、名称、模板图片、官网落地页、二维码尺寸与坐标、邀请码坐标/宽度/字号、启用状态和排序值。读取接口统一返回规范化模板列表；旧配置自动迁移成一个默认模板。

管理端提供模板列表和编辑器：新增、复制、删除、启用/停用、排序、上传模板、拖拽二维码和邀请码、实时预览、保存发布。至少保留一个启用模板，管理员预览使用示例邀请码，发布后代理端读取最新配置。

代理端通过认证的 `/api/app/distribution/overview` 获得 `posterTemplates`。当前邀请码仅由服务端返回，代理不可修改；客户端仅允许选择模板，并在本机生成官网 URL `?agentCode=` 与二维码。上次选择的模板 ID 存入本地偏好，模板不存在或停用时回退到首个启用模板。

Flutter 代理页增加模板选择、海报预览、保存到相册和系统分享。图片生成使用现有 Flutter Canvas/图片缓存能力，权限拒绝和生成失败均展示可重试状态；未授权或无邀请码时不显示推广海报操作。

## 接口与校验

- 管理端 `GET/PUT /api/distribution-poster-config`：读写规范化模板数组。
- App 端 overview 增加 `posterTemplates`，只返回启用模板和公开布局数据，不返回管理权限字段。
- 模板图片只能是受控上传路径；落地页必须为 HTTP/HTTPS；坐标、尺寸、文字长度沿用现有范围校验。
- 保存时拒绝空模板列表和重复模板 ID；删除最后一个模板或停用最后一个启用模板返回 400。
